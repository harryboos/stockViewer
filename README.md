# 观星 A股

可在本地或私人服务器运行的简体中文 A 股观察台。它可以管理自选股、读取免费真实行情、按公开方法计算量化策略，查看大盘量能、行业概念与对应龙头股，并让 DeepSeek、GLM 5.3、Qwen 3.8 Max 各自每天完成一次 AI 选股。

![观星 A股预览](public/og.png)

> 本项目只用于个人研究。部署到私人服务器时请启用访问保护；内容不构成投资建议或收益承诺。

## 这次升级解决了什么

- A 股行情不再依赖 Tushare Token 或积分
- 主数据源使用 AKShare；主源失败时自动降级到 BaoStock
- 股票目录、自选股、行情缓存和策略结果保存在本机 SQLite
- 默认包含 15 分钟行情缓存、东方财富多域名重试、腾讯行情降级、最后成功数据保留和明确错误状态
- 三家 AI 共享完全相同的系统提示语、任务提示语、真实候选池和输出约束；同一模型同一天默认只运行一次
- 规则策略增加趋势确认、价值动量和热门概念共振，热门概念使用当日实时板块强度与上涨广度
- 新增板块概念雷达，合并行业/概念涨幅、今日成交额、较前一交易日成交额变化、涨跌广度和主力资金，提供跨行业/概念的成交额 Top 矩阵，并区分领涨龙头与资金龙头
- 大盘观察的实时量能同比按前一交易日同一时点累计成交额计算；东方财富不可用时自动切换腾讯指数分时，主力资金流也会降级到腾讯逐股汇总
- 从 GitHub 维护清晰的量化仓库适配 Qlib 精简多因子、双均线趋势与 RSI 超跌回升
- 策略页底部自动汇总多策略共识、规则覆盖、AI 完成度和数据降级提醒
- 网站运行时会在北京时间工作日 18:10 自动执行每日策略

免费数据源没有服务等级保证，页面给出的价格仍应在交易前向券商核对。

## 技术架构

```text
中文 React 界面（Vinext / TypeScript）
                │
                ▼
本地接口转发（同源 /api）
                │
                ▼
FastAPI 数据服务（Python）
       ├── AKShare：复权历史、估值与标准东方财富线路
       ├── 东方财富备用线路：实时快照、概念板块与成份股（绕过异常系统代理）
       ├── 腾讯证券备用线路：指数分时同比、全市场逐股资金流汇总
       ├── BaoStock：股票目录、历史日线、故障降级
       ├── SQLite：自选股、缓存、每日结果
       └── DeepSeek / 智谱 GLM / 阿里云百炼 Qwen 官方接口
```

前端继续保留原有界面，只把更适合 A 股数据生态的部分迁到了 Python。因此不用重做整个网站，也更方便以后加入回测、财务因子和机器学习。

代码按职责拆分：页面组件不直接保存策略元数据，行情服务不直接实现 HTTP 分页，策略编排不再混合技术指标计算。环境变量统一由 `backend/config.py` 读取并限制在合理范围，外部请求与降级逻辑也可以独立测试。

## 环境要求

- Node.js 22.13.0 或更高版本
- Python 3.11～3.13
- 可以访问所选免费行情源的网络
- 只有启用 AI 选股时才需要对应模型的 API 密钥

```bash
npm install
npm run setup
```

`npm run setup` 会在项目内创建 `.venv`，并安装 FastAPI、AKShare、BaoStock 等依赖。

## 启动

```bash
npm run dev
```

打开 <http://localhost:3000>。这一个命令会同时启动中文网站和本地数据服务。

第一次读取行情或股票目录可能需要 10～30 秒；以后会直接使用缓存。数据库文件位于 `data/stockviewer.sqlite3`。

## AI 配置

复制 `.env.example` 为 `.env.local`，只填写需要启用的模型：

```dotenv
DEEPSEEK_API_KEY=
DEEPSEEK_MODEL=deepseek-chat

GLM_API_KEY=
GLM_MODEL=glm-5.3
GLM_BASE_URL=https://open.bigmodel.cn/api/paas/v4

QWEN_API_KEY=
QWEN_MODEL=qwen3.8-max
QWEN_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
```

股票行情本身不需要密钥。AI 接口可能产生供应商费用；未配置的模型会显示“待配置”，不会使用演示结果冒充。

DeepSeek、GLM 5.3、Qwen 3.8 Max 收到完全相同的系统提示语、任务说明、候选快照与 JSON 字段约束。分析文字不设影响正常表达的短字数硬限制，卡片会对长内容提供展开与收起；后端只保留防止异常输出的宽松安全上限。三张卡片只保留模型供应商本身的差异；修改提示语后，旧版本当天缓存会自动失效并按新提示语重新运行一次。新版阿里云百炼账号可能要求使用控制台给出的工作空间专属 `compatible-mode/v1` 地址，此时请替换 `QWEN_BASE_URL`。

## 免费行情如何工作

| 顺序 | 数据源 | 主要用途 | 特点 |
| --- | --- | --- | --- |
| 1 | 东方财富 `push2delay` 备用线路 | A 股行情快照、概念板块与成份股 | 默认绕过系统代理，采用浏览器请求头、分页限速和自动重试 |
| 2 | 腾讯证券公开行情 | 大盘实时量能同比、当前主力资金流备用口径 | 东方财富历史接口失败时自动启用；资金流由全 A 股逐股数据汇总 |
| 3 | [AKShare](https://akshare.akfamily.xyz/) | 标准行情线路、前复权历史、估值和股息率 | 备用线路不可用时再尝试，避免每次先触发已知代理错误 |
| 4 | [BaoStock](https://www.baostock.com/) | 股票目录、历史日线、PE/PB、最终故障降级 | 无需密钥、自有服务器；以日线为主，不是盘中实时源 |

实时行情会优先访问与 AKShare 字段兼容的东方财富备用域名，并先绕过操作系统代理；若网络必须使用代理，会自动再尝试系统线路。备用域名失败后才调用 AKShare 标准接口，最后再降级到 BaoStock 最近交易日日线。界面右上角会标出当前实际使用的数据源。

大盘扩展数据使用独立缓存，不再随着页面缓存版本升级而失效。实时量能同比会分别重试并缓存沪市、深市指数，东方财富失败后切换腾讯最近 5 个交易日指数分时；两个网络源都失败时才使用当日最近成功缓存。主力资金流优先使用东方财富历史口径，失败时以腾讯全 A 股逐股资金流汇总当天数据并逐日留存。两种资金流统计口径不完全相同，页面会在指标和图表中标出每个结果的实际来源。

全市场快照默认缓存 15 分钟，主线路失败后 30 分钟内不重复冲击上游。可以通过 `SPOT_CACHE_SECONDS`、`PRIMARY_FAILURE_BACKOFF_SECONDS`、`EASTMONEY_PAGE_DELAY_SECONDS` 调整。除非排查问题，不建议关闭 `EASTMONEY_DELAY_ENABLED`。

## 每日规则策略

这些策略不是复制官方指数，而是在当前流动性候选池中借鉴公开编制思路重新排序；强势缩量为用户自定义严格筛选，热门概念使用独立的实时概念板块候选池：

| 策略 | 实际因子 | 公开方法来源 |
| --- | --- | --- |
| 红利低波 / 价值低波 | 股息率可用时纳入；否则使用正 PE、PB 与 120 日波动降级 | [上证红利质量指数方法](https://www.sse.com.cn/market/sseindex/diclosure/c/c_20250123_10770595.shtml) |
| 价格动量 | 近半年动量、近一年动量、成交流动性 | [创业板动量成长指数方法](https://www.cnindex.com.cn/docs/gz_399296.pdf) |
| 小盘低波 | 120 日收益波动、市值、成交流动性 | [巨潮小盘低波指数方法](https://www.cnindex.com.cn/docs/gz_399408.pdf) |
| Qlib 精简多因子 | 5/20/60 日收益、MA20 偏离、5/20 日量能、波动和流动性 | [microsoft/qlib Alpha158](https://github.com/microsoft/qlib/blob/main/qlib/contrib/data/loader.py) |
| 双均线趋势 | 现价＞MA10＞MA30、20 日收益为正、均线强度、波动和流动性 | [kernc/backtesting.py SmaCross](https://github.com/kernc/backtesting.py/blob/master/doc/examples/Strategies%20Library.py) |
| RSI 超跌回升 | 14 日 Wilder RSI 三日前低于 45、当前回升但低于 60、5 日收益为正、现价高于 MA5 | [QuantConnect LEAN RsiAlphaModel](https://github.com/QuantConnect/Lean/blob/master/Algorithm.Framework/Alphas/RsiAlphaModel.py) |
| 趋势确认 | 现价＞MA20＞MA60、20/60 日动量为正、低波动、成交流动性 | [创业板动量成长指数方法](https://www.cnindex.com.cn/docs/gz_399296.pdf) |
| 价值动量 | 正 PE、正 PB、60 日与半年动量、成交流动性 | [国证 AlphaFocus 单因子指数系列](https://www.cnindex.com.cn/zh_information/notices_news/2021/202105/t20210525_17317.html?act_menu=2) |
| 强势缩量筛选 | 昨额＞10亿、10日涨幅＞30%、20日均额＞12亿、量比＜1.5、今日涨幅＜11% | 用户自定义规则 |
| 热门概念共振 | 当日概念涨幅、上涨家数占比、个股涨幅和成交额；剔除 ST、退市整理、涨幅≥11% 和成交额不足 1 亿元 | [AKShare 概念板块与成份股接口](https://akshare.akfamily.xyz/data/stock/stock.html) |

候选样本数默认是 18，可以在 `.env.local` 通过 `STRATEGY_SAMPLE_SIZE` 调整为 12～40。热门概念默认取强度靠前的 5 个，可以通过 `HOT_CONCEPT_LIMIT` 调整为 3～8。样本越多，第一次计算越慢，也越容易触发免费源限流。

热门概念要求板块当日涨幅为正且上涨家数多于下跌家数，再对成份股排序。当天成功结果写入 SQLite；若实时概念源不可用且当天没有成功缓存，页面显示空结果，不会把旧日期热点或模拟股票当作今日结果。

“最近 10 个交易日涨幅”按最新可用价格相对 10 个交易日前收盘价计算；“最近 20 个交易日日均成交额”包含最新交易日。AKShare 可用时直接采用盘中量比；降级到 BaoStock 日线时，量比按最新成交量 ÷ 前 5 日平均成交量估算。任一指标缺失时，该股票不会入选，也不会用接近条件的股票补位。

## GitHub 策略口径

项目只选择有明确源码、参数和维护主体的仓库，并优先采用能用现有 OHLCV 日线复现的方法。页面中的实现是针对 A 股候选池的透明适配，不是原项目完整模型或原样回测结果：

- Qlib 策略使用 Alpha158 公开的 ROC、MA、STD 与成交量滚动因子族，但不运行机器学习训练流程。
- 双均线策略沿用 SmaCross 的短长均线信号，将参数适配为 MA10/MA30 并增加流动性与波动排序。
- RSI 策略采用 LEAN 使用的 14 日 Wilder RSI；只有形成回升且未进入高位时才给出结果。

GitHub 星标、开源许可或示例代码都不等于策略有效性证明。新增方法仍需用 A 股历史数据做独立样本外回测，纳入手续费、滑点、涨跌停、停牌和幸存者偏差后，才能评价其稳定性。

## 页面总结

策略页最底部的“今日策略总结”会合并规则策略与已成功运行的 AI 结果。股票至少被两种独立方法选中才进入“多策略共识”；同时显示规则完成数、AI 完成数、不重复候选数量，以及热门概念、严格筛选和降级数据源的提示。共识只表示方法重合，不代表上涨概率或投资建议。

## 每日运行

网站保持运行时，内置任务会在北京时间工作日 18:10 自动执行。时间可以修改：

```dotenv
ENABLE_DAILY_SCHEDULER=true
DAILY_RUN_HOUR=18
DAILY_RUN_MINUTE=10
```

也可以手动运行：

```bash
npm run daily
```

若设置了 `DAILY_RUN_SECRET`，手动任务会自动携带密钥。策略页的“今日策略状态”只补齐当天缺失或失败的结果，已成功的 AI 不会重复调用；需要完全重新计算时，可以点击“手动重跑全部”。页面会先提示确认，然后重新获取行情、重算全部规则策略并再次调用所有已配置的 AI，因此可能产生新的接口费用。

## 本地接口

### 板块概念 AI 推荐

「板块概念」页新增「近期强势概念推荐」。点击「生成当日推荐」后，后台收集行情并固定调用 GLM 5.3（`glm-5.3`），页面自动读取进度与结果；切换页面不会重复发起分析。按北京时间每天缓存，重新分析今天会再次调用 AI。复用现有 `GLM_API_KEY` 和 `GLM_BASE_URL`，无需另外选择供应商；`GLM_MODEL` 不覆盖本模块的固定模型，缺少 GLM 密钥时会提示配置。该模块独立于每日三家 AI 选股，不随定时选股重复运行。

推荐在概念涨幅榜和成交额榜中最多 12 个活跃方向内比较，优先选择近 5 日或近 10 日涨幅为正的概念。历史接口失败、数据不足或近 5 日回调不再直接导致候选全部被清空：有当日上涨表现的方向可作为「当日活跃观察」，明确提示「近期趋势待确认」，缺失涨幅显示“—”。近 10 日仍有正收益的方向不会仅因近 5 日回调而被排除。若当前候选确实没有近期或当日强势方向，返回正常的空推荐说明。成功取得的收盘历史按交易日缓存，盘中历史只作短时缓存，避免次日误用未收盘数据。

每个概念展示当日涨跌、成交额、主力净流入、上涨广度及家数、可用的近 5/10 日累计涨幅，以及最多 3 只强势股的行情和理由。成份股候选取涨幅前 100 名中同一交易日上涨、成交额至少 1 亿元的正常股票，排除 ST/退市标签；成份股行情缺失时显示提示，不补造名单。非交易日明确展示最近交易日日期。

「现实催化」与「行情如何验证」分开展示。先使用智谱 [Web Search API](https://docs.bigmodel.cn/cn/guide/tools/web-search)（`search_std`，复用 GLM 密钥）检索近 30 天的现实事件，搜索受限或无有效结果时回退到东方财富财经资讯。检索词包含概念同义词及产业上下游词，例如制糖扩展到白糖、天气、产量与供需；这些词只用于寻找线索，不预设某事件已经发生。联网检索可能产生服务商费用，仅在点击生成时运行，与分析结果一起按日缓存。

GLM 5.3 必须分别说明「发生了什么 → 如何传导到供需、价格、成本、订单或盈利 → 对该概念的影响」。有报道支持的事件必须引用本概念真实检索来源，并展示日期、原文链接与可展开的摘录；没有证据时明确标为待验证机制。模型不能仅用资金流入或股价上涨充当现实原因，不能将盘后新闻倒推为前一交易日上涨原因，也不能把天气传导的示例当成当下事实。所有行情数字、名称与链接由服务端数据填充，模型只负责筛选和解释。

概念推荐使用 **GLM 5.3 MAX**：模型 ID 为 `glm-5.3`，`thinking.type=enabled`，`reasoning_effort=max`。生成任务在后台运行，扩展行情与资讯检索分别最多等待 40 秒和 25 秒，模型请求最多等待 8 分钟，整个任务最多等待 10 分钟。部分数据失败时尽量保留可用结果。概念任务的数据库运行锁保留 11 分钟，避免 MAX 分析超过原来的 3 分钟后被误判中断并重复调用；其他每日 AI 选股保留原有超时设置。此次提示词版本更新会使此前低推理档位的推荐缓存失效。复用现有 SQLite 数据库，无需迁移或安装新依赖。

## 常见问题

### 页面提示 AKShare 已降级

系统会依次尝试东方财富备用线路、AKShare 标准线路和 BaoStock。如果仍显示 BaoStock，通常是两个东方财富域名都被当前网络限流、拦截或上游接口再次调整。只要右上角有交易日期，网站仍在使用真实日线数据；页面会在失败冷却时间结束后自动重试实时源。

当前已知的 macOS `127.0.0.1` 系统代理问题由备用线路自动绕过，无需关闭整台电脑的代理。需要确认实际连接方式时，查看 `GET /api/system` 返回的 `dataSource.transport`、`health` 和 `error`。

### 搜索第一次很慢

首次会同步约 5,000 只正常上市 A 股；同步完成后搜索直接查询本地 SQLite。股票目录每天最多自动同步一次。

### 如何清空所有本地数据

先停止网站，再移动或删除 `data/stockviewer.sqlite3`。下次启动会创建新数据库并恢复默认自选股。此操作会清除自选股和历史策略结果，请先备份该文件。

### 是否适合商业交易系统

不适合。AKShare 和 BaoStock 适合个人研究与原型，没有交易级服务承诺。商业使用、自动下单或需要毫秒级行情时，应采购交易所授权数据并增加账户、审计、监控和灾备能力。

### 预测 Tab：未来半个月强势概念

「预测」Tab 包含前瞻预测与历史反馈，固定使用 **GLM 5.3 MAX**（`glm-5.3`、`thinking.type=enabled`、`reasoning_effort=max`）。窗口为北京时间生成日次日起的 **15 个自然日**，含周末、节假日；例如 9 月 12 日生成时预测区间为 9 月 13–27 日。仅点击生成才调用模型与联网检索；切换 Tab 只读取状态，结果按生成日独立缓存，不覆盖板块概念推荐或每日选股。

预测比较涨幅榜、成交额榜的最多 12 个活跃概念，允许保留短期回调方向，最多输出 3 个潜在强势方向。每个方向展示行情、强势股票、技术面／基本面／时事新闻三方面判断、现实事件的影响传导、预测确认条件与失效条件。技术指标由服务端根据真实历史计算：MA5/10/20、Wilder RSI14、距 20 日最高收盘价、近期收益、完整 5 日成交额比；成交额比剔除行情当日，避免将盘中值与全天值直接比较。历史日期不一致则不计算当前技术指标。

基本面材料包括已取得强势成份股的动态 PE、PB、总市值及近 30 日检索到的公告、订单、供需、商品价格和产业政策资料；**未接入完整财务报表**，不能将成份股估值当作全板块估值，不能编造收入或利润增速。搜索会关注未来两周可能影响预期的变量，但具体未来事件日期必须有报道支持。所有来源链接、行情字段与预测日期均由服务端填充；来源不足标为待验证，技术历史或基本面覆盖不足时研究把握度最多为「较低」。把握度不是统计胜率，没有足够证据时允许不输出名单。

提示词核心是：比较趋势延续、回调修复和催化轮动机会，解释「为什么现在、为什么在未来半个月可能体现」，用现实事件→供需／价格／成本／订单→盈利预期的链条说明原因，主动考虑反面证据，并给出可观察的确认与失效条件。完整提示词见 `backend/concept_forecast.py` 的 `SYSTEM_INSTRUCTION` 和 `build_prompt()`。每次调用会附上真实候选材料、已核对的历史反馈与严格的输出结构。预测任务单独使用 `forecast:glm` 运行锁，与概念推荐一样最多分析 10 分钟、锁保留 11 分钟；启动时自动新增档案与反馈表，无需增加配置项。

预测接口的高峰容错：后端以流式方式接收 GLM 5.3 MAX，页面仍只展示核对后的完整报告。连接建立失败、临时限流（1302）、平台过载（1305）及可重试的 5xx 最多尝试 5 次，以约 5/10/20/40 秒加随机延迟退避，并遵守更长的 `Retry-After`；全部模型请求和重试等待合计最多 8 分钟。余额、额度、套餐、权限及参数错误直接提示原因，不自动重试；已接受的流式请求若中断或输出被截断，不自动重放，不保存残缺报告。兼容接口若返回普通 JSON，也必须明确正常完成才接纳。错误分类依据[智谱业务错误码](https://docs.bigmodel.cn/cn/api/api-code)。

行情收集最多占用 85 秒；同步行情请求若仍在后台运行，后续生成共享这次请求，避免反复重试堆积线程。历史反馈读取最多 5 秒，失败时明确标记未参考历史复盘，仍继续当前预测；资讯保留原来的 25 秒预算。提示词去除重复序列化的技术和估值数据，保留完整新闻摘录、指标及来源。数据库读写移出预测启动的异步请求线程，减少锁等待阻塞其他接口的风险。总任务仍限制 10 分钟，不因高峰重试延长运行锁。

排查时查看后端 `forecast_failed`（阶段、耗时、原因）与 `forecast_glm_retry`（尝试次数、等待时间、HTTP／业务错误码）日志，可区分行情超时、账户限流、平台过载、连接中断和格式核对失败；启用 INFO 日志还可看到 `forecast_stage`。日志不记录提示词、密钥、新闻正文或模型思考内容。启动接口只提交后台任务，浏览器每次读取状态无需等待模型生成完成；切换页面或刷新状态不会重新调用模型。

### 历史预测与反馈口径

每次成功预测在同一事务中追加到 `forecast_reports`，保存发布时间、模型、提示词版本、原始行情、所选股票和原始判断。重生成不会改写旧档案，失败、过期工作进程及重复完成不会产生新档案。首次启用时导入仍存在且有完成时间的真实预测缓存，不能恢复已被覆盖或已清理的旧预测。列表使用小体积摘要，完整报告只在展开时读取。

`forecast_feedback` 保存每版本、每概念的 15/30 自然日反馈，以及用于核对的概念 OHLC 路径、起止价格、同区间基准价格和数据来源。收益基准为预测窗口内、实际发布之后首个交易日开盘价；终点为窗口末日或此前最近交易日收盘价。30 天从同一起点延伸，不代表模型曾做出一个月预测。只有截至北京时间 15:10 后的完整日线可用于当日结算；采用新浪交易日历，覆盖不足或概念日线不连续时等待补齐，不能用工作日猜测节假日。概念使用东方财富原概念指数日线，不用名称相似但成份不同的其他板块替代；基准日线提供腾讯备用源。

- 概念涨幅 = `(末日收盘 / 首日开盘 - 1) × 100%`。最高/最低涨幅分别使用期间最高/最低价；最大回撤按收盘路径及起始开盘计算。
- 统计单位是每个生成日首次成功预测中的每个概念，等权算术平均；8% 与 10% 的平均为 9%。重生成版本可查看但不纳入汇总，空名单记为观望。
- 上涨命中率 = 已到期有效样本中涨幅大于零的比例。未到期与缺数据不作零收益处理，也不进入分母。
- 基准为上证指数（000001）和科创50（000688）。超额收益为同一起止日期的概念涨幅减基准涨幅，单位为**百分点**；跑赢率为超额大于零的比例。每个基准单独显示配对样本数，缺失基准不影响概念自身收益统计。
- 重叠区间与同一概念重复出现不是独立样本，统计并非资金组合收益，未计交易成本；小样本不外推未来胜率。

服务启动时补查，运行期间每天 16:20–22:20 每小时核对一次，独立于付费 AI 定时开关；也可手动更新。更新通过跨进程租约避免并发重复请求，每分钟最多启动一次，每批最多 12 个版本，按上次核对时间轮转，已完整完成的版本不再拉取，跟踪中且当日收盘行情完整的记录当天不重复拉取。数据源故障不会覆盖已核对结果，基准缺口可后补。关闭本地服务期间不会执行，到下一次启动补查。

下一次 GLM 5.3 MAX 预测会收到生成之前已经核对的 15/30 天统计和最多 12 条近期案例（保留原逻辑、确认/失效条件、实际收益及超额），提示其检查追涨、催化过期及证据缺口；未到期或之后才获知的结果不进入材料。不额外发起 AI 复盘调用，不声称价格结果证明某个新闻因果或条件已发生，也不进行模型训练。无已到期样本时明确仍在积累。

### 数据库精简与保留期限

本地数据库启动时自动迁移：移除未使用的仓位比例字段，停止保存无人读取的目录来源和调试状态项，并将它们改为服务日志。迁移前使用 SQLite 备份接口保存一份同目录的 `stockviewer.before-storage-v1.sqlite3`（自定义数据库名时采用对应文件名），包含 WAL 中已经提交的数据；已有备份不会被覆盖，也不参与自动清理。迁移保留自选顺序、添加时间、股票目录、行情、提示词版本、运行令牌及成交量单位迁移标记。

清理在每次启动时检查，服务持续运行时每天北京时间 04:00 检查，不依赖每日 AI 选股开关，也不会触发行情请求或模型调用：

| 数据 | 保留规则 |
| --- | --- |
| 成功的 AI 选股、概念推荐、预测每日缓存以及规则策略结果 | 保留 90 天内的记录，超过 90 天清理 |
| 原始预测档案、15/30 天反馈及核对价格 | 长期保留，不受每日缓存 90 天清理影响；仅保存实际预测涉及的概念和基准 |
| 失败的 AI 任务及运行锁已过期的遗留任务 | 保留 14 天内的记录；有效运行锁保护中的任务不删除 |
| 热点、昨日成交额、每日分时成交额对比缓存 | 最近 7 个有数据的交易日，且数据日期不超过 30 个自然日；利用已有快照日期，不把周末当交易日 |
| 概念历史 K 线缓存 | 每个概念最近两次完整历史窗口，新窗口写入时即清理多余旧副本；窗口内 K 线保留完整 |
| 已不再读取的旧缓存版本、未使用状态项 | 自动清理；仍有读取用途的兼容缓存、未知元数据和较新格式保留 |
| 股票目录、自选股、每股最新行情、运行与迁移标记 | 保留 |

AI 研究报告在数据库内部对相同新闻来源去重，各分析段落通过编号引用同一份摘录；技术指标和估值来源中重复序列化的指标文本改为引用报告内的快照字段。写入使用紧凑 JSON，仅在能减少体积时采用去重格式。读取时恢复原来的页面数据结构，旧版报告仍可读取，新闻日期、链接、完整摘录及预测依据不丢失。首次迁移也会精简已有可读取报告，格式异常的旧记录保留原样。

预测 Tab 可读取长期档案及反馈；其余模块仍主要读取当天结果。常规清理释放的 SQLite 页面供后续写入复用，不在每日任务中执行会锁库的全库压缩。
