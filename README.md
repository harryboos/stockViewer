# 观星 A股

可在本地或私人服务器运行的简体中文 A 股观察台。它可以管理自选股、读取免费真实行情、按公开方法计算量化策略，查看大盘量能、行业概念与对应龙头股，提供明确点击后运行的 AI 选股、DeepSeek Flash · MAX 概念预测与历史表现核对。

![观星 A股预览](public/og.png)

> 本项目只用于个人研究。部署到私人服务器时请启用访问保护；内容不构成投资建议或收益承诺。

## 这次升级解决了什么

- A 股行情不再依赖 Tushare Token 或积分
- 主数据源使用 AKShare；主源失败时自动降级到 BaoStock
- 股票目录、自选股、行情缓存和策略结果保存在本机 SQLite
- 默认包含 15 分钟行情缓存、东方财富多域名重试、腾讯行情降级、最后成功数据保留和明确错误状态
- 三家 AI 共享完全相同的系统提示语、任务提示语、真实候选池和输出约束；同一模型同一天默认只运行一次
- 规则策略增加趋势确认、价值动量和热门概念共振，热门概念使用当日实时板块强度与上涨广度
- 新增板块概念雷达，合并行业/概念涨幅、今日成交额、较前一交易日成交额变化、涨跌广度和主力资金，提供跨行业/概念的成交额 Top 矩阵，并区分领涨龙头与资金龙头
- 大盘观察的实时量能同比按前一交易日同一时点累计成交额计算；东方财富不可用时自动切换腾讯指数分时，主力资金流也会降级到腾讯逐股汇总
- 从 GitHub 维护清晰的量化仓库适配 Qlib 精简多因子、双均线趋势与 RSI 超跌回升
- 策略页底部自动汇总多策略共识、规则覆盖、AI 完成度和数据降级提醒
- 网站运行时会在北京时间工作日 18:10 自动计算免费规则策略；AI 默认由页面按钮触发

免费数据源没有服务等级保证，页面给出的价格仍应在交易前向券商核对。

## 技术架构

```text
中文 React 界面（Vinext / TypeScript）
                │
                ▼
本地接口转发（同源 /api）
                │
                ▼
FastAPI 数据服务（Python）
       ├── AKShare：复权历史、估值与标准东方财富线路
       ├── 东方财富备用线路：实时快照、概念板块与成份股（绕过异常系统代理）
       ├── 腾讯证券备用线路：指数分时同比、全市场逐股资金流汇总
       ├── BaoStock：股票目录、历史日线、故障降级
       ├── SQLite：自选股、缓存、每日结果
       └── DeepSeek / 智谱 GLM / 阿里云百炼 Qwen 官方接口
```

前端继续保留原有界面，只把更适合 A 股数据生态的部分迁到了 Python。因此不用重做整个网站，也更方便以后加入回测、财务因子和机器学习。

代码按职责拆分：页面组件不直接保存策略元数据，行情服务不直接实现 HTTP 分页，策略编排不再混合技术指标计算。环境变量统一由 `backend/config.py` 读取并限制在合理范围，外部请求与降级逻辑也可以独立测试。

## 环境要求

- Node.js 22.13.0 或更高版本
- Python 3.11～3.13
- 可以访问所选免费行情源的网络
- 只有启用 AI 选股时才需要对应模型的 API 密钥

## 第一次安装

```bash
npm install
npm run setup
```

`npm run setup` 会在项目内创建 `.venv`，并安装 FastAPI、AKShare、BaoStock 等依赖。

## 启动

```bash
npm run dev
```

打开 <http://localhost:3000>。这一个命令会同时启动中文网站和本地数据服务。

第一次读取行情或股票目录可能需要 10～30 秒；以后会直接使用缓存。数据库文件位于 `data/stockviewer.sqlite3`。

## 私人服务器部署

统一私人首页、Caddy、共享访问密钥和 Docker Compose 已拆分到同级的 `private-apps-gateway` 项目；本项目只负责股票应用及其镜像构建。服务器真实配置统一保存在仓库外的 `/opt/private-apps/config/private-apps.env`，避免应用项目更新或重建目录时丢失密钥。

完整部署与更新流程见 [私人服务器部署文档](docs/server-deployment.md)。`deploy/` 只保留股票应用镜像所需的 `Dockerfile.stock`；首页、证书、路由和服务编排均由 gateway 项目统一管理。

## AI 配置

复制 `.env.example` 为 `.env.local`，只填写需要启用的模型：

```dotenv
DEEPSEEK_API_KEY=
DEEPSEEK_MODEL=deepseek-flash
DEEPSEEK_BASE_URL=https://api.deepseek.com

GLM_API_KEY=
GLM_MODEL=glm-5.3
GLM_BASE_URL=https://open.bigmodel.cn/api/paas/v4

QWEN_API_KEY=
QWEN_MODEL=qwen3.8-max
QWEN_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
```

股票行情本身不需要密钥。AI 接口可能产生供应商费用；未配置的模型会显示“待配置”，不会使用演示结果冒充。

DeepSeek、GLM 5.3、Qwen 3.8 Max 收到完全相同的系统提示语、任务说明、候选快照与 JSON 字段约束。分析文字不设影响正常表达的短字数硬限制，卡片会对长内容提供展开与收起；后端只保留防止异常输出的宽松安全上限。三张卡片只保留模型供应商本身的差异；修改提示语后，旧版本当天缓存会失效，下一次明确点击生成时使用新提示语。新版阿里云百炼账号可能要求使用控制台给出的工作空间专属 `compatible-mode/v1` 地址，此时请替换 `QWEN_BASE_URL`。

## 免费行情如何工作

| 顺序 | 数据源 | 主要用途 | 特点 |
| --- | --- | --- | --- |
| 1 | 东方财富 `push2delay` 备用线路 | A 股行情快照、概念板块与成份股 | 默认绕过系统代理，采用浏览器请求头、分页限速和自动重试 |
| 2 | 腾讯证券公开行情 | 沪深京行情快照、大盘实时量能同比、当前主力资金流备用口径 | 东方财富失败时切换独立提供方；校验分页总数、重复代码，并换算成交额与市值单位 |
| 3 | [AKShare](https://akshare.akfamily.xyz/) | 标准行情线路、前复权历史、估值和股息率 | 备用线路不可用时再尝试，避免每次先触发已知代理错误 |
| 4 | [BaoStock](https://www.baostock.com/) | 股票目录、历史日线、PE/PB、最终故障降级 | 无需密钥、自有服务器；以日线为主，不是盘中实时源 |

实时行情优先访问与 AKShare 字段兼容的东方财富备用域名，并先绕过操作系统代理；若网络必须使用代理，会自动再尝试系统线路。备用域名失败后先切换腾讯沪深京行情，再尝试 AKShare 标准接口（同样依赖东方财富），个股最后可降级到 BaoStock 最近交易日日线。腾讯排行使用 GET 的 `board_code=aStock` 参数；报价日期取自腾讯指数实际行情时间，盘前不会把昨日收盘标成今日。全量分页有 60 秒预算，完整结果在进程内复用 60 秒，供行情和资金流共享。界面标明实际使用的数据源。

板块页和新概念研究默认试用**同花顺公开行情**，可通过后端 `SECTOR_DATA_SOURCE=eastmoney` 切回东财（修改后重启服务）。同花顺使用公开目录和带 `updateTime` 的独立报价，概念最多核验 48 个候选、行业最多 12 个。概念目录超过 48 个时，读取 24 个涨幅排序候选与 24 个按代码分散探索的候选，交替安排；探索以首批真实报价的交易日期为种子，节假日不会因抓取日期变化而换一批样本。日期探针也计入 48 个总数；探针失败时使用固定种子并标记日期未知，其余候选仍可读取。共享 4 个工作线程与 24 秒板块读取预算不变，期限后不再排入新请求。页面分别展示目录、已核实映射、本批请求、同日有效和可用快照数；未报价目录不进入预测或同期对照范围。这是有限样本，不代表全市场。未取得的资金流、昨日成交额和动态 PE 留空，公开成员页也只覆盖部分股票；强势股另外核验与概念同一交易日、上涨且成交额不少于 1 亿元。访问限制直接停止，不绕过登录或验证码；超时或失败保留最近同来源快照。此配置覆盖板块页、概念推荐、新预测及对应的轮动/复盘；「热门概念共振」规则策略仍使用东财。

同花顺新概念以 `THS:88xxxx` 留档，日线、对照范围和缓存独立保存，后续同期最强仅比较该次保存的同花顺样本。原有 `BK…` 预测继续读取原东财指数，不用同名同花顺概念替换，旧预测的数据缺口仍需原来源恢复。原东财 BK 概念可选配置后端 `TUSHARE_TOKEN`，通过 Tushare `dc_daily` 查询同代码指数；授权要求以[官方文档](https://tushare.pro/document/2?doc_id=382)为准（目前为6000积分）。历史复盘的上证指数、科创50保持腾讯 → 新浪 → 东方财富备用链。可运行 `npm run probe:sources -- --start 2026-09-18 --end 2026-09-21` 只读检查各历史源；详见[数据源实测报告](docs/data-sources-2026-09-22.md)。

板块刷新失败时，可在出问题的服务器运行 `npm run probe:sources -- --boards`，分别检查东方财富备用线路与 AKShare 的行业、概念列表。输出有效行数、来源报价日期、耗时与安全错误类别；缺少报价时间会明确标注，不能据此认定已更新到最近交易日。每项检查使用独立进程，默认硬超时 75 秒、最多 2 项并发；可用 `--board-timeout 30` 缩短检查预算，或 `--board-sources eastmoney` 只查一路。较短预算超时不代表应用自身 60 秒分页预算也必然失败。这是独立来源诊断，不运行完整板块聚合，不初始化或写入业务数据库，也不调用 AI；两条线路都依赖东方财富，并非两个独立提供方。结果只代表执行机器的网络，本机检查不能证明服务器线路可用。

大盘全量行情都不可用时，读取内存或数据库中 `latest-market` 的最近成功快照；页面顶部明确标注缓存、行情日期和原更新时间，不刷新成功时间，也不把旧数据写成新快照。尚无成功快照时才返回暂不可用。后台更新遇到这种降级仍记为失败，可重试。`RemoteDisconnected` 表示上游或中间网络主动断开，单凭异常无法断定服务器 IP 被限流；东方财富备用域名与 AKShare 的东方财富接口不是独立提供方。

大盘扩展数据使用独立缓存，不再随着页面缓存版本升级而失效。实时量能同比会分别重试并缓存沪市、深市指数，东方财富失败后切换腾讯最近 5 个交易日指数分时；两个网络源都失败时才使用当日最近成功缓存。主力资金流优先使用东方财富历史口径，失败时以腾讯全 A 股逐股资金流汇总当天数据并逐日留存。两种资金流统计口径不完全相同，页面会在指标和图表中标出每个结果的实际来源。

全市场快照默认缓存 15 分钟，主线路失败后 30 分钟内不重复冲击上游。可以通过 `SPOT_CACHE_SECONDS`、`PRIMARY_FAILURE_BACKOFF_SECONDS`、`EASTMONEY_PAGE_DELAY_SECONDS` 调整。除非排查问题，不建议关闭 `EASTMONEY_DELAY_ENABLED`。

## 每日规则策略

这些策略不是复制官方指数，而是在当前流动性候选池中借鉴公开编制思路重新排序；强势缩量为用户自定义严格筛选，热门概念使用独立的实时概念板块候选池：

| 策略 | 实际因子 | 公开方法来源 |
| --- | --- | --- |
| 红利低波 / 价值低波 | 股息率可用时纳入；否则使用正 PE、PB 与 120 日波动降级 | [上证红利质量指数方法](https://www.sse.com.cn/market/sseindex/diclosure/c/c_20250123_10770595.shtml) |
| 价格动量 | 近半年动量、近一年动量、成交流动性 | [创业板动量成长指数方法](https://www.cnindex.com.cn/docs/gz_399296.pdf) |
| 小盘低波 | 120 日收益波动、市值、成交流动性 | [巨潮小盘低波指数方法](https://www.cnindex.com.cn/docs/gz_399408.pdf) |
| Qlib 精简多因子 | 5/20/60 日收益、MA20 偏离、5/20 日量能、波动和流动性 | [microsoft/qlib Alpha158](https://github.com/microsoft/qlib/blob/main/qlib/contrib/data/loader.py) |
| 双均线趋势 | 现价＞MA10＞MA30、20 日收益为正、均线强度、波动和流动性 | [kernc/backtesting.py SmaCross](https://github.com/kernc/backtesting.py/blob/master/doc/examples/Strategies%20Library.py) |
| RSI 超跌回升 | 14 日 Wilder RSI 三日前低于 45、当前回升但低于 60、5 日收益为正、现价高于 MA5 | [QuantConnect LEAN RsiAlphaModel](https://github.com/QuantConnect/Lean/blob/master/Algorithm.Framework/Alphas/RsiAlphaModel.py) |
| 趋势确认 | 现价＞MA20＞MA60、20/60 日动量为正、低波动、成交流动性 | [创业板动量成长指数方法](https://www.cnindex.com.cn/docs/gz_399296.pdf) |
| 价值动量 | 正 PE、正 PB、60 日与半年动量、成交流动性 | [国证 AlphaFocus 单因子指数系列](https://www.cnindex.com.cn/zh_information/notices_news/2021/202105/t20210525_17317.html?act_menu=2) |
| 强势缩量筛选 | 昨额＞10亿、10日涨幅＞30%、20日均额＞12亿、量比＜1.5、今日涨幅＜11% | 用户自定义规则 |
| 热门概念共振 | 当日概念涨幅、上涨家数占比、个股涨幅和成交额；剔除 ST、退市整理、涨幅≥11% 和成交额不足 1 亿元 | [AKShare 概念板块与成份股接口](https://akshare.akfamily.xyz/data/stock/stock.html) |

候选样本数默认是 18，可以在 `.env.local` 通过 `STRATEGY_SAMPLE_SIZE` 调整为 12～40。热门概念默认取强度靠前的 5 个，可以通过 `HOT_CONCEPT_LIMIT` 调整为 3～8。样本越多，第一次计算越慢，也越容易触发免费源限流。

热门概念要求板块当日涨幅为正且上涨家数多于下跌家数，再对成份股排序。当天成功结果写入 SQLite；若实时概念源不可用且当天没有成功缓存，页面显示空结果，不会把旧日期热点或模拟股票当作今日结果。

“最近 10 个交易日涨幅”按最新可用价格相对 10 个交易日前收盘价计算；“最近 20 个交易日日均成交额”包含最新交易日。AKShare 可用时直接采用盘中量比；降级到 BaoStock 日线时，量比按最新成交量 ÷ 前 5 日平均成交量估算。任一指标缺失时，该股票不会入选，也不会用接近条件的股票补位。

## GitHub 策略口径

项目只选择有明确源码、参数和维护主体的仓库，并优先采用能用现有 OHLCV 日线复现的方法。页面中的实现是针对 A 股候选池的透明适配，不是原项目完整模型或原样回测结果：

- Qlib 策略使用 Alpha158 公开的 ROC、MA、STD 与成交量滚动因子族，但不运行机器学习训练流程。
- 双均线策略沿用 SmaCross 的短长均线信号，将参数适配为 MA10/MA30 并增加流动性与波动排序。
- RSI 策略采用 LEAN 使用的 14 日 Wilder RSI；只有形成回升且未进入高位时才给出结果。

GitHub 星标、开源许可或示例代码都不等于策略有效性证明。新增方法仍需用 A 股历史数据做独立样本外回测，纳入手续费、滑点、涨跌停、停牌和幸存者偏差后，才能评价其稳定性。

## 页面总结

策略页最底部的“今日策略总结”会合并规则策略与已成功运行的 AI 结果。股票至少被两种独立方法选中才进入“多策略共识”；同时显示规则完成数、AI 完成数、不重复候选数量，以及热门概念、严格筛选和降级数据源的提示。共识只表示方法重合，不代表上涨概率或投资建议。

## 每日运行

网站保持运行时，内置任务会在北京时间工作日 18:10 自动计算免费规则策略。AI 默认不随定时任务执行；只有主动设置 `ENABLE_SCHEDULED_AI=true` 才开启定时 AI 选股。时间可以修改：

```dotenv
ENABLE_DAILY_SCHEDULER=true
ENABLE_SCHEDULED_AI=false
DAILY_RUN_HOUR=18
DAILY_RUN_MINUTE=10
```

也可以手动运行：

```bash
npm run daily
```

若设置了 `DAILY_RUN_SECRET`，手动任务会自动携带密钥。`npm run daily` 是明确执行规则与缺失 AI 的命令，可能产生模型费用。页面的“今日策略状态”只读取 AI 状态并取得规则结果；“更新规则策略”只重算免费规则。AI 区域提供“生成未完成 AI”“只重试失败”与单个失败模型重试，数据与任务页也可以针对单个已完成任务重新生成。重新生成期间及失败后保留上次成功内容和时间。

### AI 提示词与证据边界（2026-10-16 迭代）

当前三类提示词的完整静态指令及输出结构见 [提示词汇总](docs/ai-prompts-current.txt)，实际调用还会注入当次真实候选、日期、新闻和可用反馈。历史 v5 预测提示词仍保留供对照。版本变化只影响下一次生成和当日缓存匹配，不改写历史预测或收益记录。

| 任务 | 当前版本 | 证据与输出范围 |
| --- | --- | --- |
| 每日 AI 个股选股（已配置的三家模型共用） | `6` | 只比较最新有效同日的价格、涨跌幅和成交额，选择 0–3 只；未提供历史量价、财报或新闻，不得凭公司名称补造趋势或催化。没有有效行情时直接报数据不足，不调用模型。 |
| 近期强势概念推荐 | `concept-v6-deepseek-flash-max` | 比较近期表现与现实催化，允许 0–3 个概念和空催化；近 5/10 日任一正收益不等于连续走强。 |
| 未来半个月概念预测 | `forecast-v10-complete-history-deepseek-flash-max` | 先核验最近 21 个交易日价格覆盖，再结合技术、经营证据、时事及已到期反馈，比较反转、延续与催化增量；允许观望，不把后验赢家当成当前推荐。 |

概念推荐与半个月预测改为固定使用 **DeepSeek Flash · MAX**，模型 ID 为 `deepseek-flash`；`DEEPSEEK_MODEL` 仅控制普通每日个股选股，不覆盖这两个研究模块。普通每日 DeepSeek 选股的默认模型也为 `deepseek-flash`，GLM 和 Qwen 卡片保留各自配置。旧 GLM 预测仍按原模型与版本展示和复盘，不重写为 DeepSeek。个股分数只代表本次候选内优先级，不是胜率；多策略共识按共同入选次数排列，不再混合不同模型及规则的原始评分。

`backend/research_prompt.py` 统一校验概念证据的归属、类型、重复标识、链接和截止时间，生成与结果组装使用相同边界；日期未知或晚于 `decisionAt` 的新闻不作为已报道证据。只有日期的资讯保留精度，页面不再把零点显示成真实发表时刻；同日行情快照之后的新闻标为后续变量，不能倒推解释此前上涨。`publishedAt` 不证明首发时间，报道存在也不证明因果。来源匹配是结构校验，不代替对文章内容真实性和文字推断的判断。

待验证假设误附合法的本概念背景引用时，服务器移除引用并在概念卡片说明修正，保留假设状态、不提高研究把握度，不因这类可保守修正的格式问题丢弃整份分析或重新付费调用模型。虚构、跨概念、类型不符、超过截止时间的引用仍拒绝；已证实判断仍必须具有匹配来源。这次版本变化修复生成可用性，不代表预测准确率已经提高。

预测的基本面 `supported` 必须引用与经营事实相关的新闻或公告；估值字段仅作背景，不能给订单、盈利增长盖上“有依据”标签。无现实事件可输出空催化，无估值不否定已有经营证据。新增测试覆盖空名单、混合日期、无效报价、未来或越界引用、日期精度、空催化和未校准评分混算；未用模型生成的样例当作真实收益验证，效果仍待后续到期样本检验。

### 板块概念 AI 推荐

「板块概念」页新增「近期强势概念推荐」。点击「生成当日推荐」后，后台收集行情并固定调用 DeepSeek Flash（`deepseek-flash`）的 MAX 推理，页面自动读取进度与结果；切换页面不会重复发起分析。按北京时间每天缓存，重新分析今天会再次调用 AI。使用 `DEEPSEEK_API_KEY` 和 `DEEPSEEK_BASE_URL`（默认 `https://api.deepseek.com`），无需另外选择供应商；`DEEPSEEK_MODEL` 不覆盖本模块的固定模型，缺少 DeepSeek 密钥时会提示配置。新推荐与预测分别使用 `concept:deepseek`、`forecast:deepseek` 命名空间；旧 GLM 成功缓存不会冒充新模型结果，正在执行的旧任务按实际模型显示并避免并发重复生成。该模块独立于每日三家 AI 选股，不随定时选股重复运行。

推荐在概念涨幅榜和成交额榜中最多 12 个活跃方向内比较，优先选择近 5 日或近 10 日涨幅为正的概念。历史接口失败、数据不足或近 5 日回调不再直接导致候选全部被清空：有当日上涨表现的方向可作为「当日活跃观察」，明确提示「近期趋势待确认」，缺失涨幅显示“—”。近 10 日仍有正收益的方向不会仅因近 5 日回调而被排除。若当前候选确实没有近期或当日强势方向，返回正常的空推荐说明。成功取得的收盘历史按交易日缓存，盘中历史只作短时缓存，避免次日误用未收盘数据。

每个概念展示当日涨跌、成交额、主力净流入、上涨广度及家数、可用的近 5/10 日累计涨幅，以及最多 3 只强势股的行情和理由。成份股候选取涨幅前 100 名中同一交易日上涨、成交额至少 1 亿元的正常股票，排除 ST/退市标签；成份股行情缺失时显示提示，不补造名单。非交易日明确展示最近交易日日期。

「现实催化」与「行情如何验证」分开展示。新闻搜索独立于分析模型：已配置 `GLM_API_KEY`、`GLM_BASE_URL` 时，先使用智谱 [Web Search API](https://docs.bigmodel.cn/cn/guide/tools/web-search)（`search_std`）检索近 30 天的现实事件；未配置、搜索受限或无有效结果时回退到东方财富财经资讯。DeepSeek 密钥只用于 DeepSeek 分析，不发送给智谱搜索接口；仅配置 DeepSeek 也可生成，但搜索覆盖取决于可用的公开资讯。检索词包含概念同义词及产业上下游词，例如制糖扩展到白糖、天气、产量与供需；这些词只用于寻找线索，不预设某事件已经发生。联网检索可能产生服务商费用，仅在点击生成时运行，与分析结果一起按日缓存。

模型必须分别说明「发生了什么 → 如何传导到供需、价格、成本、订单或盈利 → 对该概念的影响」。有报道支持的事件必须引用本概念真实检索来源，并展示日期、原文链接与可展开的摘录；没有证据时明确标为待验证机制。模型不能仅用资金流入或股价上涨充当现实原因，不能将盘后新闻倒推为前一交易日上涨原因，也不能把天气传导的示例当成当下事实。所有行情数字、名称与链接由服务端数据填充，模型只负责筛选和解释。

概念推荐使用 **DeepSeek Flash · MAX**：模型 ID 为 `deepseek-flash`，`thinking.type=enabled`，`reasoning_effort=max`，使用 JSON 输出与流式接收。生成任务在后台运行，扩展行情与资讯检索分别最多等待 40 秒和 25 秒；接入与重试退避共享 3 分钟预算，模型接入后的分析预算为 8 分钟，整个任务最多 805 秒（约 13.4 分钟），数据库运行锁保留 865 秒。部分数据失败时尽量保留可用结果，不因流式接入等待挤占完整分析时间；其他每日 AI 选股保留各自时限。新模型使用独立命名空间，旧结果仍保留原始模型与版本。复用现有 SQLite 数据库，无需安装新依赖。

## 常见问题

### 页面提示 AKShare 已降级

系统会依次尝试东方财富备用线路、AKShare 标准线路和 BaoStock。如果仍显示 BaoStock，通常是两个东方财富域名都被当前网络限流、拦截或上游接口再次调整。只要右上角有交易日期，网站仍在使用真实日线数据；页面会在失败冷却时间结束后自动重试实时源。

当前已知的 macOS `127.0.0.1` 系统代理问题由备用线路自动绕过，无需关闭整台电脑的代理。需要确认实际连接方式时，查看 `GET /api/system` 返回的 `dataSource.transport`、`health` 和 `error`。

### 搜索第一次很慢

首次会同步约 5,000 只正常上市 A 股；同步完成后搜索直接查询本地 SQLite。股票目录每天最多自动同步一次。

### 如何清空所有本地数据

先停止网站，再移动或删除 `data/stockviewer.sqlite3`。下次启动会创建新数据库并恢复默认自选股。此操作会清除自选股和历史策略结果，请先备份该文件。

### 是否适合商业交易系统

不适合。AKShare 和 BaoStock 适合个人研究与原型，没有交易级服务承诺。商业使用、自动下单或需要毫秒级行情时，应采购交易所授权数据并增加账户、审计、监控和灾备能力。

### 预测 Tab：未来半个月强势概念

「预测」Tab 包含前瞻预测与历史反馈，固定使用 **DeepSeek Flash · MAX**（`deepseek-flash`、`thinking.type=enabled`、`reasoning_effort=max`）。窗口为北京时间生成日次日起的 **15 个自然日**，含周末、节假日；例如 9 月 12 日生成时预测区间为 9 月 13–27 日。仅点击生成才调用模型与联网检索；切换 Tab 只读取状态，结果按生成日独立缓存，不覆盖板块概念推荐或每日选股。

预测 v10 先在当前来源的有效概念快照中发现机会，再最多研究 12 个概念。生成时增加两路有时间预算的事件搜索，以实际概念名称匹配线索，再由模型核对主体、时间及传导；匹配不代表新利好。历史读取优先复用截至决策时已存在的同代码、同口径行情；短期缓存不足时先补读，不能因缓存命中就跳过技术完整性检查。额外最多请求 48 个概念及两个基准：榜单、按日期轮换的分散样本和事件线索交错安排，避免有限预算只研究热门方向。候选必须按交易日历核验截至行情快照日期的最近 21 个交易日，缺日、无效价格或日期未对齐的方向补读后仍不完整，就不进入 AI；旧格式快照的已有范围也应用同一门槛，不能绕过检查。日历不可用或覆盖不足时不生成缺少核验依据的预测。门槛只检查价格覆盖，不要求正收益；盘中最后一根仍未收盘，不能把已覆盖交易日说成全部已收盘。随后按当日涨幅、上涨广度、相对成交额、3/5 日动量改善、事件线索、同区间相对强度和成交额八路轮转入池，允许短期负收益但改善的方向；缺失数据不补 0。

页面区分实际快照数、通过 21 交易日核验数和进入 AI 数，并说明日历是否可用。折叠详情最多展示 8 个未通过的概念及有限缺失日期；未读取、请求失败与已核对的历史缺口分开，不把未读空结果说成已确认缺日。同花顺仍为有限公开样本；两路搜索不能覆盖全部新闻，旧快照没有完整发现字段时沿用旧范围并明确提示，更新板块行情可扩大范围。行情收集总预算保持 85 秒；取得快照后的发现阶段最多 55 秒，其中历史读取最多 24 秒、成份股最多 18 秒，沿用共享有界线程池。未完成请求不等于没有历史数据。

没有任何候选通过技术历史门槛时，任务标记为失败，保留覆盖与缺口诊断供页面展示，并跳过模型调用；不写成成功预测或观望档案，也不占用当日首版统计资格。只有存在合格候选、模型完成比较后主动输出空名单，才属于可统计的观望。

每个方向展示行情、强势股票、技术面／基本面／新闻判断、现实事件传导、确认与失效条件。技术指标由服务端计算 MA5/10/20、Wilder RSI14、距 20 日最高收盘价、近期收益、5 日成交额比，以及 3/20 日收益、前段收益、动量变化、均线偏离、MA5 斜率、上涨次数与收盘回撤。成交额比剔除行情当日，不将盘中值与完整交易日比较；“动量改善”可能仍是下跌减速，并非已经反转。日期不一致的当前指标留空，不设置未经验证的买卖阈值。

提供同日期 5/10 日相对上证、科创50收益差，以及入选方向之间最多 20 个日收益的相关性、强势股样本重合和共同新闻链接。来源、实际观察区间、样本量和缺口随指标保存并展示；当前版本的概念与基准历史先按交易日历检查最近 21 个交易日，指标仅使用已核验的连续区间。旧报告没有这项核验信息时保持原记录，不追溯宣称已通过。相关性少于 10 对或收益无波动时未知；样本重合不是全体成份股重合，共同 URL 也不等于已识别全部转载。只用这些信息提示共同风险，不据此构造组合仓位。

基本面材料包括已取得强势成份股的动态 PE、PB、总市值及近 30 日检索到的公告、订单、供需、商品价格和产业政策资料；**未接入完整财务报表**，不能将成份股估值当作全板块估值，不能编造收入或利润增速。搜索会关注未来两周可能影响预期的变量，但具体未来事件日期必须有报道支持。所有来源链接、行情字段与预测日期均由服务端填充；来源不足标为待验证。技术历史未通过门槛直接排除，入池后任一分析面缺乏依据或缺少已报道催化时研究把握度最多为「较低」；单独缺失估值不否定已有经营新闻。把握度不是统计胜率，没有足够证据时允许不输出名单。

提示词核心是：比较趋势延续、回调修复和催化轮动机会，解释「为什么现在、为什么在未来半个月可能体现」，用现实事件→供需／价格／成本／订单→盈利预期的链条说明原因，主动考虑反面证据，并给出可观察的确认与失效条件。完整提示词见 `backend/concept_forecast.py` 的 `SYSTEM_INSTRUCTION`、`build_prompt()`、`backend/forecast_review.py` 的 `REVIEW_INSTRUCTION` 及共同证据规则。当前版本明确技术历史准入只证明价格覆盖，不证明未来胜率或现实催化；沿用阶段判断、真实相对收益与共同风险数据，不固定偏好任何概念。每次调用会附上真实候选材料、已核对的历史反馈与严格的输出结构；未通过核验概念的明细保留在档案与页面，不发送给模型充当候选。预测任务单独使用 `forecast:deepseek` 运行锁；时间预算集中定义在 `backend/forecast_limits.py`，整个任务最多 25.5 分钟，运行锁保留 26.5 分钟，避免长时间推理期间重复生成。概念推荐使用单独的 805 秒任务预算。启动时自动新增档案与反馈表，无需增加配置项。

v5 的 `candidateAudit` 保存生成时所有模型候选的简要指标、入池通道、新闻标题/日期/链接及最终是否入选，帮助区分召回与排序问题；不保存模型思考、不回填旧报告。`historicalFeedback.missedLeaderCases` 另提供最多 4 个已到期且已核对的同源、同观察区间漏选对照：核对时间晚于本次预测、未到期或区间不匹配的结果不进入提示，范围不全明确标记，相同赢家的重叠区间合并。旧档案没有候选审计时只能标记“是否入池未知”。这是输入与提示词迭代，不是模型参数训练或已证明的收益提升；仍需后续样本外到期结果检验。

新预测同时冻结两条简单对照规则：当前快照涨幅前三、模型候选等权。冻结名单与模型选择分开保存，不把基线名单塞入提示词影响决策。核对同期行情时优先读取入选概念及这些对照，后台从同一观察区间的已到期完整结果计算严格配对收益；任何一项缺失就不纳入该对照均值，不补 0。预测档案增加按提示词版本、行情来源和 15/30 日观察期分组的评估：完整报告收益、个别概念最大回撤均值、观望率、非重叠报告数、基线超额、覆盖内排名及可核实的漏选归因。个别回撤均值不是组合回撤，30 日是延伸观察；重叠报告不独立，不同日期版本的描述性差异不证明因果提升。旧报告没有冻结输入时不补造对照。

预测接口的高峰容错：后端以流式方式接收 DeepSeek Flash · MAX，页面仍只展示核对后的完整报告。连接建立失败、临时限流或可重试的服务错误最多尝试 5 次，以约 5/10/20/40 秒加随机延迟退避，并遵守更长的 `Retry-After`；接入等待与退避共享 3 分钟预算。DeepSeek 可能在 HTTP 200 后先发送保活或等待信息，只有收到实际推理或正文内容才启动完整的 20 分钟分析预算；保活不会被误认为分析进度或无限延长排队。连接连续 3 分钟未收到数据会终止等待；实际输出中的分析受独立的 20 分钟上限约束。余额、认证、权限及参数错误直接提示原因，不自动重试；已接受的流式请求若中断或输出被截断，不自动重放，不保存残缺报告。兼容接口若返回普通 JSON，也必须明确正常完成才接纳。DeepSeek 与旧 GLM 分别识别各自错误，不把智谱业务错误码套用到 DeepSeek。

行情收集最多占用 85 秒；同步行情请求若仍在后台运行，后续生成共享这次请求，避免反复重试堆积线程。历史反馈读取最多 5 秒，失败时明确标记未参考历史复盘，仍继续当前预测；资讯保留原来的 25 秒预算。提示词去除重复序列化的技术和估值数据、压缩结构序列化，保留完整新闻摘录、指标及来源；要求输出简洁、避免各分析字段重复论述，仍保留 MAX 推理和全部事实核验约束。数据库读写移出预测启动的异步请求线程，减少锁等待阻塞其他接口的风险。外层任务时限覆盖行情、反馈、资讯、接入、分析及核对的预算之和，运行锁额外保留 60 秒供结果落库。

排查时查看后端 `forecast_failed`（阶段、耗时、原因）与 `forecast_deepseek_retry`（尝试次数、等待时间、错误原因）日志，可区分行情超时、账户限流、平台过载、连接中断和格式核对失败；启用 INFO 日志还可看到 `forecast_stage` 与 `forecast_deepseek_stage`。旧 GLM 任务仍使用对应的 `forecast_glm_retry`／`forecast_glm_stage` 标签。页面读取当前运行的实际模型与阶段，区分等待接入、MAX 推理和报告整理，不显示伪造的完成百分比。日志不记录提示词、密钥、新闻正文或模型思考内容。启动接口只提交后台任务，浏览器每次读取状态无需等待模型生成完成；切换页面或刷新状态不会重新调用模型。

### 历史预测与反馈口径

每次成功预测在同一事务中追加到 `forecast_reports`，保存发布时间、模型、提示词版本、原始行情、所选股票和原始判断。重生成不会改写旧档案，失败、过期工作进程及重复完成不会产生新档案。首次启用时导入仍存在且有完成时间的真实预测缓存，不能恢复已被覆盖或已清理的旧预测。列表使用小体积摘要，完整报告只在展开时读取。

`forecast_feedback` 保存每版本、每概念的 15/30 自然日反馈，以及用于核对的概念 OHLC 路径、起止价格、同区间基准价格和数据来源。收益基准为预测窗口内、实际发布之后首个交易日开盘价；终点为窗口末日或此前最近交易日收盘价。30 天从同一起点延伸，不代表模型曾做出一个月预测。只有截至北京时间 15:10 后的完整日线可用于当日结算；采用新浪交易日历，覆盖不足或概念日线不连续时等待补齐，不能用工作日猜测节假日。概念始终按留档代码读取原提供方日线，不用名称相似但成份不同的其他板块替代；基准日线提供腾讯备用源。

- 概念涨幅 = `(末日收盘 / 首日开盘 - 1) × 100%`。最高/最低涨幅分别使用期间最高/最低价；最大回撤按收盘路径及起始开盘计算。
- 统计单位是每个生成日首次成功预测中的每个概念，等权算术平均；8% 与 10% 的平均为 9%。重生成版本可查看但不纳入汇总，空名单记为观望。
- 上涨命中率 = 已到期有效样本中涨幅大于零的比例。未到期与缺数据不作零收益处理，也不进入分母。
- 基准为上证指数（000001）和科创50（000688）。超额收益为同一起止日期的概念涨幅减基准涨幅，单位为**百分点**；跑赢率为超额大于零的比例。每个基准单独显示配对样本数，缺失基准不影响概念自身收益统计。
- 重叠区间与同一概念重复出现不是独立样本，统计并非资金组合收益，未计交易成本；小样本不外推未来胜率。

服务启动时补查，运行期间每天 16:20–22:20 每小时核对一次，独立于付费 AI 定时开关；也可手动更新。更新通过跨进程租约避免并发重复请求，每分钟最多启动一次，每批最多 12 个版本，按上次核对时间轮转，已完整完成的版本不再拉取，跟踪中且当日收盘行情完整的记录当天不重复拉取。数据源故障不会覆盖已核对结果，基准缺口可后补。关闭本地服务期间不会执行，到下一次启动补查。

如果“当前涨幅”和“同期最强”同时为空，先查看概念日线是否可用，不能理解为必须等半个月到期才会显示。未到期也展示截至最近完整收盘的阶段收益。连接失败、空响应或缺失区间内交易日都会保留此前已核对结果；仅实际返回的历史能够确认缺口时才展示具体缺失日期，尚未读到的数据单独标为等待查询。任务标为失败或未完整核对，不再把返回空列表算作成功。两个模块复用同一概念历史缓存。历史接口对每个域名先尝试直连，再尝试已配置的系统代理，共享 25 秒请求预算；代理故障不会阻止第二个域名的直连尝试。东财历史增加 `7.push2his.eastmoney.com` 备用入口，但它仍与其他东财域名处于同一提供方故障域，不等于独立数据源，不能保证网络故障时一定补齐。

例如 9 月 17 日预测、窗口从 9 月 18 日开始，在 9 月 22 日盘前需要 9 月 18 日与 9 月 21 日的概念日线。若这两个日期缺失，不能填入 0% 或用个股均值替代。大盘腾讯备用源不等于东方财富概念指数备用源；上游恢复后分别点击“更新实际表现”和“核对同期最强”，不需要重新生成 AI 预测。对照模块区分尚未核对、日线缺失和仅有较早区间结果，并展示最近尝试核对时间。

下一次 DeepSeek Flash · MAX 预测会收到生成之前已经核对的 15/30 天统计和最多 12 条近期案例（保留原逻辑、确认/失效条件、实际收益及超额），提示其检查追涨、催化过期及证据缺口；未到期或之后才获知的结果不进入材料。不额外发起 AI 复盘调用，不声称价格结果证明某个新闻因果或条件已发生，也不进行模型训练。无已到期样本时明确仍在积累。

### 数据库精简与保留期限

本地数据库启动时自动迁移：移除未使用的仓位比例字段，停止保存无人读取的目录来源和调试状态项，并将它们改为服务日志。迁移前使用 SQLite 备份接口保存一份同目录的 `stockviewer.before-storage-v1.sqlite3`（自定义数据库名时采用对应文件名），包含 WAL 中已经提交的数据；已有备份不会被覆盖，也不参与自动清理。迁移保留自选顺序、添加时间、股票目录、行情、提示词版本、运行令牌及成交量单位迁移标记。

清理在每次启动时检查，服务持续运行时每天北京时间 04:00 检查，不依赖每日 AI 选股开关，也不会触发行情请求或模型调用：

| 数据 | 保留规则 |
| --- | --- |
| 成功的 AI 选股、概念推荐、预测每日缓存以及规则策略结果 | 保留 90 天内的记录，超过 90 天清理 |
| 原始预测档案、15/30 天反馈及核对价格 | 长期保留，不受每日缓存 90 天清理影响；同期对照另存冻结概念范围与紧凑收益结果，不保存全市场逐日路径 |
| 失败的 AI 任务及运行锁已过期的遗留任务 | 保留 14 天内的记录；有效运行锁保护中的任务不删除 |
| 热点、昨日成交额、每日分时成交额对比缓存 | 最近 7 个有数据的交易日，且数据日期不超过 30 个自然日；利用已有快照日期，不把周末当交易日 |
| 概念历史 K 线缓存 | 每个概念最近两次完整历史窗口，新窗口写入时即清理多余旧副本；窗口内 K 线保留完整 |
| 已不再读取的旧缓存版本、未使用状态项 | 自动清理；仍有读取用途的兼容缓存、未知元数据和较新格式保留 |
| 股票目录、自选股、每股最新行情、运行与迁移标记 | 保留 |

AI 研究报告在数据库内部对相同新闻来源去重，各分析段落通过编号引用同一份摘录；技术指标和估值来源中重复序列化的指标文本改为引用报告内的快照字段。写入使用紧凑 JSON，仅在能减少体积时采用去重格式。读取时恢复原来的页面数据结构，旧版报告仍可读取，新闻日期、链接、完整摘录及预测依据不丢失。首次迁移也会精简已有可读取报告，格式异常的旧记录保留原样。

预测 Tab 与策略历史成绩均可读取长期档案及反馈。常规清理释放的 SQLite 页面供后续写入复用，不在每日任务中执行会锁库的全库压缩。


## 全项目研究功能

- **每日摘要**：汇总自选波动、大盘与概念热点、最近策略名单、半个月及一个月预测反馈。使用已有数据，不额外调用 AI；每个模块标明数据日期。
- **个股详情**：点击自选、策略、板块强势股或摘要中的股票，查看最近 60 根前复权日 K 线与成交量、已采集的概念关联、历史入选原因和带日期的新闻。三类资料独立加载，行情失败不阻塞新闻；概念关系只反映已采集范围，不声称完整覆盖。
- **自选研究记录**：按分组、关注时间、涨跌幅或名称查看，编辑关注理由与观察笔记。新关注股票记录当时取得的行情参考价及行情日期，旧记录不补造参考价；参考价不是实际成交成本。初次打开先显示已保存列表，再更新免费行情。
- **板块轮动**：5/10/20 个完整交易日收盘涨幅、近 26 日日线走势、相对 5 个交易日前的排名升降。两次排名使用同一批完整覆盖概念；最新上涨广度单独标明快照时间。日线分批补齐，缺失概念不按零涨幅参与排名。
- **数据与任务中心**：查看各模块最近成功数据时间、来源异常、后台核对进度、单项重试、下一次规则计算时间，以及今日 AI 生成任务和分析请求次数。请求次数不等于账单金额，不包括新闻搜索。概念与预测始终使用 DeepSeek Flash · MAX。

### 规则与 AI 历史成绩

从本次升级起，所有规则及每日 AI 选股在同一天保留首次成功名单，强制重算不改写这一统计样本。已有数据库仅导入实际留存版本，标明“升级前留存版本，无法确认是否当日首版”，不恢复或伪造被覆盖的名单。历史结果以实际保存时间之后的首个交易日开盘开始，观察 5/10/20 个交易日；盘中发布的名单从次一交易日开始。

只使用完整且日期一致的前复权日线。缺失或停牌期间不拼接成完整窗口，已到期完整样本才计入平均涨幅、上涨比例、收盘最大回撤、相对上证指数／科创50的收益与超额；基准各自显示配对样本数。个股等权，重叠样本不独立，不是可执行的组合净值，未计手续费、滑点与成交限制。已经核对的最终价格保留，后续只补齐缺失的同区间基准。

### 预测与同期最强概念对照

每个预测档案新增“同期最强概念对照”，随半个月／一个月切换。所有概念使用与该预测一致的首个可观察交易日开盘、最近完整收盘或期末收盘；展示同期最强、前五名、预测概念在已覆盖范围中的排名、预测概念平均涨幅及与最强的百分点差距。

新预测保存当时可取得的有效概念范围，模型提示词不包含这个全量对照列表，也不读取未来最强结果。旧预测无法恢复当时概念范围时，在首次核对保存当前列表，并明确标记范围差异。页面展示核对数量和范围日期，未全覆盖时只称“已覆盖范围最强”。行情不连续、缺失或起止日期不一致的结果不进排名；即使所有概念下跌，也按实际负收益比较。事后最强仅用于复盘，不纳入预测命中率，也不是当时可知的推荐。

研究核对默认在服务运行期间每天北京时间 16:05—22:50，每 15 分钟分批执行，不调用 AI。选股样本与轮动概念沿用各自批次限制；同期对照按共享线程容量和时间预算读取，同一任务由数据库租约防止重复运行。对照优先读取预测入选项与冻结基线，并在各优先级内按最近尝试时间公平轮转，避免某份报告或固定失败概念长期挤占全部名额；同代码的不同观察窗口合并请求所需范围。不同提供方分别执行有界批次，东财持续失败不会阻止同花顺范围的读取。历史与指数读取共享缓存，并发最多每批 4 路，避免一次请求拉取所有板块。任务中心或各模块按钮可手动继续补齐；网络异常保留此前取得的结果与真实日期。

月度对照复用按代码保存的日线归档，按实际观察窗口判断是否完整；完整区间直接复用，缺口只增量请求相邻重叠区间。合并必须同代码、来源名称与来源链接一致，且重叠日期的开盘、最高、最低、收盘价一致；无重叠、来源变化或价格矛盾时重新取得独立完整序列，不能直接拼接。已有价格与已核对收益在补读失败时保留，缺口仍不计零收益，也不参与不完整排名。这能避免每天窗口变化就丢失可复用历史，但已经清理且上游仍不可用的行情无法凭缓存补造。

新增加的选股档案、收益反馈、预测对照范围与收益结果长期保留；通用短期日线、新闻缓存保留 7 天，同代码日线归档单独保留最多 260 根，未更新 180 天后清理，避免月度对照尚未完成就随短期缓存被删除。AI 调用计数明细保留 30 天，各模块最近成功摘要保留一份。未增加页面状态持久化、备份导出或条件提醒。

### 代码维护与运行边界

- 自选读取、增删、刷新和笔记保存统一由 `lib/use-watchlist.ts` 管理。启动时先展示缓存；操作开始后取消旧读取，并核对响应所属请求，避免迟到的行情响应覆盖刚保存的自选或笔记。
- 客户端 JSON 请求设置覆盖响应正文的 190 秒等待上限，保留主动取消的语义。预测仍通过短请求读取后台状态，等待上限不会缩短模型的后台分析时间。日期、涨跌幅与金额格式集中在 `lib/format.ts`，缺失或非有限数值不显示为零。
- 轮动、策略成绩、同期最强对照和预测反馈共用 `backend/research_pool.py` 的 8 个行情工作线程，每批最多占用 4 个。超时的请求在实际结束前继续占用原来的名额，不建立无限队列；其余待核对项留给后续批次。来源失败时保留可核对的其他结果，已完成结果的保护规则继续生效。
- 预测反馈的数据库读取与任务领取移到后台线程。请求断开不会中断领取和启动之间的交接；写入最终状态失败也会释放本进程的运行锁。
- 预测历史在同一读取事务中取得总数、每日首版和当前页版本，仅载入这些档案的反馈，并在读取时排除列表不用的价格路径。摘要只查询最近 5 份策略名单；任务中心读取 AI 状态时不展开完整报告；个股新闻缓存命中时不再读取预测或选股档案。新增的缓存时间和 AI 调用时间索引在启动时自动建立。

提交改动前可运行 `npm run check`，顺序完成类型检查、代码检查、前端测试、后端测试和生产构建。回归覆盖迟到响应、正文读取超时、用户取消、并发任务领取、批量请求超时、部分来源失败及历史首版统计口径；测试使用临时数据库和模拟服务，不调用付费 AI。

| 新接口 | 用途 |
| --- | --- |
| `PATCH /api/watchlist` | 更新分组、关注理由、笔记 |
| `GET /api/watchlist?cached_only=true` | 立即读取已保存列表和行情，不等待网络 |
| `GET /api/research/stock?code=600519&part=profile` | 股票基础资料、关联概念及历史入选；`part=history/news` 独立读取日线或资讯 |
| `GET /api/research/digest` | 只读每日摘要 |
| `GET /api/research/rotation` | 5/10/20 日轮动及覆盖范围 |
| `GET /api/research/selections?sessions=10&page=1&strategy=` | 历史选股表现，周期可选 5/10/20 交易日 |
| `GET /api/research/comparison?report_id=1&days=15` | 同期最强概念对照，周期可选 15/30 自然日 |
| `GET /api/research/operations` | 数据健康、任务和 AI 请求计数 |
| `GET/POST /api/research/jobs?key=rotation` | 查询／后台执行单项任务：rules、selections、rotation、comparison、market、sectors |
| `POST /api/strategies/ai?provider=glm` | 仅执行指定模型；`failed_only=true` 只重试失败项 |

后台写入任务沿用运行密钥与前端同源保护；读取任务状态不会自动生成付费分析。数据库升级随启动执行，无需新依赖。

交易日历由行情、预测反馈及研究任务共享。解析使用项目已有的 Node.js 独立进程（10 秒上限，脚本执行 5 秒上限），避免多个后台任务初始化原生 JavaScript 库时导致 Python 服务退出；失败时优先读取原有日历，覆盖不足则明确等待数据，不凭工作日推算复盘收益。
