# 代码审阅与优化记录 · 2026-09-07

已审阅前端页面与组件、同源 API 代理、Python 行情和策略服务、SQLite 持久化、启动脚本、构建与部署配置及现有测试。改动保留现有架构、依赖版本和策略条件；本轮重点是可复现的正确性问题、重复请求、数据一致性和失败恢复。

开始时 lint、TypeScript 和 22 个后端测试均通过。下列问题主要位于原测试未覆盖的并发、跨日、部分失败和部署路径，现已修复。

| 优先级 | 原问题与影响 | 修复位置与结果 |
| --- | --- | --- |
| P1 | Docker 的 `COPY . .` 会包含未排除的本地环境文件，可能把模型密钥打进镜像。 | `.dockerignore` 排除 `.env*`，保留无密钥的示例文件。未检查或重建既有服务器镜像。 |
| P1 | 实时成交量使用“手”，BaoStock 历史成交量使用“股”；合并进同一序列后，量能因子和估算量比可能出现 100 倍单位误差。 | `backend/data_sources.py` 统一内部成交量为股；`backend/database.py` 在启动事务内一次性转换旧 AKShare 缓存。 |
| P1 | 强制并发调用可重复执行模型；进程中断后，`running` 记录会一直阻止普通重试。 | `backend/ai.py` 合并同进程的在途每日请求；`backend/database.py` 通过事务原子领取模型任务，使用 180 秒租约和执行令牌。活动任务不被强制覆盖，旧执行结果也不能覆盖新任务。模型调用有 100 秒总超时，过期任务可重试。 |
| P1 | 每次初始化都会插入默认自选股，重启后恢复用户已删除的股票。 | `backend/database.py` 仅首次创建自选表时插入默认值，保留已有空列表；种子数据也不再覆盖已更新的股票名称。 |
| P1 | 降级日线或乱序响应可覆盖更新的实时行情。 | `backend/database.py` 按交易日、获取时间和数据来源控制覆盖，同日 BaoStock 日线不覆盖已有实时快照。 |
| P2 | 交易日期缓存在进程生命周期内永不失效。 | `backend/data_sources.py` 按北京时间自然日更新并加锁，去掉已有日期时仍会执行的多余日历查询。日历不可用时原有的工作日近似降级仍保留。 |
| P2 | 即使模型全部未配置或已完成，AI 接口也先请求候选行情，导致无必要的延迟，甚至无法读取成功缓存。 | `backend/ai.py` 先检查模型状态，只有确实需要运行时才取行情；同时校验模型名和提示版本。旧提示版本元数据迁移后继续复用成功结果。 |
| P2 | 一项策略请求失败时，`Promise.all` 丢弃另一项成功结果；失败后 UI 可能永久显示运行中。 | `app/page.tsx` 分别保存成功响应，失败时重新读取真实运行状态；在途任务通过只读轮询跟进，不自动重复付费调用。 |
| P2 | 搜索旧请求的回调会覆盖新请求状态，自选股增删响应也可能乱序。 | `app/page.tsx` 忽略已取消请求的回调，清理过期搜索结果，对自选变更和策略执行增加即时锁与按钮状态。 |
| P2 | 把缺失涨幅当成 0、把平盘计为上涨，并混合不同交易日计算组合均值。 | `lib/watchlist-summary.ts` 只统计最新交易日的有效数值，分别计算上涨、下跌和平盘；移除固定数组生成的装饰行情柱。 |
| P2 | 运行中或失败 AI 的旧 picks 仍进入“多策略共识”。 | `lib/strategy-summary.ts` 只纳入成功 AI，并防止同一方法重复计分。 |
| P2 | 买入关注列表已写入后，行情失败仍让添加接口返回失败，前端与数据库状态不一致。 | `backend/main.py` 保留成功添加的结果，行情错误单独记录；仅获取新加入股票的行情。 |
| P2 | 历史批量请求只依赖 BaoStock，缺失股票无法使用另一数据源。 | `backend/data_sources.py` 保留单次 BaoStock 登录，对缺失股票用最多 3 个线程补取历史；AKShare 日线请求设置超时。 |
| P2 | 大盘汇总在耗时网络请求期间一直持有行情快照锁，阻塞其他页面；同时进入规则页可能重复计算。 | 大盘使用独立锁；目录同步和规则计算各自串行化，普通规则请求在锁内再次检查缓存。空自选直接返回，不拉取全市场。目录失败不再让成功行情进入日线降级。 |
| P2 | 指数历史只返回单边市场时也计入沪深总成交额；分时比较只对齐当天，昨日数据缺失时会比较不同时点。 | `backend/data_sources.py` 仅合并沪深均有数据的日期；`backend/eastmoney.py` 和 `backend/tencent.py` 对齐两个指数、两个交易日的共同时间点，腾讯累计数据先排序。 |
| P2 | 上游第一页为空但总数很大时可能产生大量无效分页请求；部分数据会被误当成全市场结果。 | 东方财富客户端拒绝空第一页、异常总数和提前结束的分页；腾讯客户端拒绝少于已知总数的结果。 |
| P2 | 因子并列时逆向排名偏斜，非有限值可能使排名异常；先四舍五入再排序还会丢失真实分差。 | `backend/strategy_factors.py` 使用二分查找与并列平均名次，处理 NaN/Infinity，并使用原始分数排序、股票代码稳定打破平局。每次排名查询由线性扫描变为二分查找；未宣称端到端速度提升比例。 |
| P2 | 代理可能携带服务器密钥执行跨站触发的 AI POST；超时和错误 HTML 都缺少准确状态。 | `lib/backend.ts` 拒绝跨站修改请求，兼容 HTTPS 网关的浏览器同源请求；超时返回 504，成功状态下的非法 JSON 返回 502，正常 API 响应禁用缓存。网关鉴权仍是现有部署前提。 |
| P3 | 添加弹窗缺少浏览器原生的焦点约束与 Escape 关闭；AI 时间使用浏览器本地时区。 | 弹窗改为原生 `dialog`，补搜索标签和长度限制、键盘焦点样式，AI 完成时间统一显示北京时间。 |
| P3 | 自定义后端端口未传给前端默认地址，启动子进程错误未处理，Python 检测只检查是否存在。 | `scripts/` 补充后端 URL 推导、子进程错误处理、手动每日任务超时和密钥去空格，校验 Python 3.11～3.13；忽略生成的 TypeScript 增量文件。 |

成交量转换依据 AKShare 官方接口对“成交量”的单位定义，并与 BaoStock 接口数据组合编写回归样例。[AKShare 股票数据文档](https://akshare.akfamily.xyz/data/stock/stock.html)

测试从原有 22 个后端用例增加到 49 个，新增 10 个前端用例。构建仍有 Vinext 对首页静态分类的提示，HTTP 检查确认首页可正常响应；Starlette 测试客户端有依赖弃用提示，本轮没有为此升级依赖。

本轮没有调用付费 AI，没有发布或修改线上服务，也没有执行浏览器交互测试或真实行情全链路测试。因此结果证明本地代码、回归样例和构建可用，不代表外部免费行情或模型 API 在当前网络下一定可用。

新版本首次启动会自动迁移 SQLite 的 AI 运行字段和成交量单位。规则缓存版本已更新，以重新计算受到单位和排名修复影响的结果；未改变的 AI 模型与提示版本继续复用当天成功缓存。
