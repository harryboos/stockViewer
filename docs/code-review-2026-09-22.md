# 代码审阅与优化记录 · 2026-09-22

本轮检查覆盖页面组件、API 代理、行情适配、策略因子、预测和选股复盘、AI 任务、SQLite 读写及运行脚本。重点修复数据口径、缺失行情、并发取消和失败状态中的可复现问题。

## 已修复问题

| 领域 | 原问题及影响 | 处理结果 |
| --- | --- | --- |
| 历史行情切换 | 只要最后一天有价格就停止切换数据源，首日或中间缺失仍无法核算收益。 | 检查整个窗口是否完整；优先使用已加载的交易日历识别节假日，避免无必要的备用请求。始终保留同一来源的完整序列，不拼接不同指数口径。 |
| 行情合法性 | 概念研究可能接收日期越界、高低价矛盾等异常日线；腾讯异常响应结构可能中断备用链。 | 统一日期和 OHLC 校验，剔除异常日线，负成交额标为缺失，异常响应继续走备用源。 |
| 全市场快照 | 重复分页、分页期间总数变化可能被当成完整快照，影响市场宽度、成交额和板块成份统计。 | 校验代码唯一性、分页总数一致性和最终数量，拒绝不完整快照。 |
| 请求等待 | 东方财富多个地址和代理路径重复重试，单项辅助数据可能长时间占用工作线程。 | 分页使用共享 60 秒重试预算；分时及资金流使用共享 25 秒重试预算。只有配置了代理才增加代理路线，并按剩余预算缩短连接和读取超时。预算用于限制后续请求，底层网络超时不等于严格的总耗时保证。 |
| 估值口径 | 动态市盈率被写入 `peTtm`，与滚动十二个月盈利口径混用。 | 仅将明确的 TTM 字段写入 `peTtm`；腾讯 TTM 正确保留，只有动态市盈率时 TTM 显示缺失。 |
| 历史策略因子 | 新行情缓存可能把快照日期之后的数据带入旧快照；直接合并旧现价和新复权历史还可能制造虚假跳涨。 | 截止于快照交易日，规范日期并去重排序。较新复权历史存在时保留统一复权序列，缺少快照当日日线则不计算该序列。规则缓存版本升至 7。 |
| 选股复盘 | 行情缺失时后台任务仍可能报成功；观察期结束后旧记录仍显示跟踪中。 | 保存已有收益和成功更新后，明确报告缺失个股或基准日线；已到期的未完成记录显示待核对，阶段收益不进入最终统计。已完成价格结果继续保留。 |
| 概念轮动 | 之前成功的缓存记录可掩盖本批全部失败，导致更新任务显示成功。 | 按本批实际补齐数量判断状态，保留成功部分并报告缺失数量。 |
| AI 并发 | 部分异步路径直接执行 SQLite 操作，锁等待阻塞状态查询；领取任务时取消可能留下无工作者的运行记录。 | 数据库操作移入工作线程；每日 AI 取消时收尾已领取任务，概念 AI 保证任务领取后交给后台执行；结束时清理上下文，替换过期任务时关闭旧执行记录。 |
| GLM 流式响应 | 对单行大小的校验发生在整行读取之后，异常上游可持续积累未换行内容。 | 增量检查缓冲长度，同时处理跨响应片段的换行符。 |
| 浏览器与代理 | 浏览器取消请求没有同步取消上游等待；成功状态的空值或非对象响应可能进入页面。 | 传递取消信号，区分取消、超时和连接失败；拒绝无效成功响应，错误响应同样禁用缓存。 |
| 股票图表 | 无效或无限数值、高低价矛盾可能生成异常图形坐标。 | 只绘制有效 OHLC；成交量无效时标为缺失，保留有效价格。 |
| 每日运行脚本 | HTTP 200 中包含 AI 失败时仍以成功状态退出，外部调度无法识别失败。 | 保留成功结果的摘要，同时返回失败退出状态并列出失败模型；不会自动重提付费任务。 |
| 预测历史读取 | 生成反馈摘要和筛选待更新报告时读取完整价格路径，增加无用 JSON 解析与内存占用。 | 查询只取必要字段，并在读取时移除不需要的价格路径。未更改档案内容及收益计算公式。 |
