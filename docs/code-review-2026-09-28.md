# 代码审阅与优化记录 · 2026-09-28

本轮检查前端请求与任务状态、行情缓存与日期、AI 接口、预测反馈、同期概念对照和存储边界。保留现有架构，针对可复现问题修复，未升级依赖或改写历史档案。

## 已完成的改动

| 范围 | 问题 | 修复及用户可见效果 |
| --- | --- | --- |
| 页面轮询 | 预测历史和概念 AI 在浏览器标签页隐藏后仍反复读取接口。 | 三处读取流程共用轮询控制；隐藏时停止后续轮询，返回时立即刷新，始终只保留一个在途读取。组件退出后忽略迟到结果。 |
| 跨页面任务状态 | 已完成或未开始的概念 AI 不再轮询，其他页面发起任务后可能一直显示旧状态。 | 返回标签页时重新读取状态；只有只读查询，不自动再次生成。 |
| 行情日期 | 只检查快照获取日期，会让“今天重新取得的旧交易日行情”通过校验。 | 同时核对行情交易日、快照时间和交易日历；拒绝未来或非法日期。休市日与开盘前可以使用已确认的最近收盘后快照，09:30 后须取得对应交易日行情。 |
| 资金流缓存 | 腾讯备用资金流只要包含当天记录，就可整天不再刷新。 | 按现有行情缓存有效期重新获取；失败时保留原数值和原更新时间，避免把旧资金流当成刚取得的数据。 |
| 普通 AI 响应 | 一次性读取整个 JSON 响应，没有大小上限；明确标记截断的内容仍可能因 JSON 可解析而进入档案。 | 逐块读取，限制解压后的累计响应为 1 MiB，异常响应及时关闭。明确标记长度截断、内容审核中断等情况时拒绝保存为成功结果；兼容未提供结束原因的网关。 |
| AI 任务阶段 | 模型配置变化后，新运行记录可能被旧尝试的“已完成”阶段覆盖。 | 阶段信息取自当前运行令牌关联的记录。 |
| 历史时间字段 | 无时区的历史发布时间会导致同期对照比较异常；无效反馈时间可能让整个历史反馈上下文失败。 | 不猜测时区，不修改旧记录。无法确认时间的样本不参与计算和模型反馈，并说明原因；有效档案继续处理。 |
| 同期最强对照 | 交易日历覆盖不足时，任务可能跳过所有窗口却显示更新成功。损坏的日历缓存还可能使读取接口报错。 | 明确区分“尚未开始”与“无法核对”；保存本批有效结果后报告缺失窗口。只读接口展示原因，不在读取时发起行情请求或改写缓存。 |
| 日历处理 | 预测概念与同期对照分别维护观察区间逻辑，并对每个概念遍历完整历史交易日历。 | 共用观察窗口校验，通过二分定位仅处理相关日期。发布后才能入场、完整收盘及 15/30 自然日口径保持一致。 |
